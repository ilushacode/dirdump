# Парсер каталогов DirDump

[![Python](https://img.shields.io/badge/python-3.10%2B-blue)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Утилита собирает дерево каталога в **один файл** - идеально для передачи
проекта нейросети (ChatGPT, Claude, Gemini) в качестве контекста.

`dirdump` уважает `.gitignore`, пропускает бинарные файлы, фильтрует по
glob-шаблонам, обрезает слишком большие файлы, оценивает количество токенов
и умеет выводить результат в трёх форматах: обычный текст, JSON, Markdown.

## Зачем это нужно

Отправить целый проект в LLM обычно означает либо упаковать его в архив
(а нейросеть архив не прочитает), либо копировать файлы по одному - это
утомительно. `dirdump` создаёт **один файл** со всем исходным кодом внутри,
аккуратно разделённым по файлам и готовым к вставке.

## Установка

Рекомендуемый способ - через [pipx](https://pipx.pypa.io/):

```bash
pipx install git+https://github.com/ilushacode/dirdump
```

Или обычным pip:

```bash
pip install git+https://github.com/ilushacode/dirdump
```

Для точного подсчёта токенов (использует `tiktoken` от OpenAI):

```bash
pipx install "dirdump[tokens] @ git+https://github.com/ilushacode/dirdump"
```

## Использование

Базовый запуск - дамп текущего каталога в `dump.txt`:

```bash
dirdump .
```

Явно указать выходной файл, отфильтровать по шаблонам и получить Markdown:

```bash
dirdump ./myproject \
    --output context.md \
    --format markdown \
    --include "*.py" --include "*.md" \
    --exclude "*test*" --exclude "migrations/*"
```

JSON - для программной обработки:

```bash
dirdump ./myproject --format json -o dump.json
```

Посмотреть все опции:

```bash
dirdump --help
```

> **Примечание для Windows.**
> Дамп сохраняется в UTF-8 без BOM.
> Если открываете файл в Блокноте — убедитесь, что кодировка выставлена
> как UTF-8. В PowerShell 7+, Windows Terminal и VS Code проблем не будет.

## Возможности

- **Учитывает `.gitignore`** - читает вложенные `.gitignore` и пропускает
  игнорируемые пути.
- **Определяет бинарные файлы** - по эвристике с нулевым байтом; бинарники
  отмечаются, но не встраиваются в дамп.
- **Фильтры `--include` / `--exclude`** - точно определяете, что попадёт
  в дамп.
- **Обрезка** - файлы больше `--max-bytes` обрезаются с пометкой.
- **Оценка токенов** - приблизительная по умолчанию, точная через
  `tiktoken`, если он установлен.
- **Три формата вывода** - `text`, `json`, `markdown`.
- **Потоковая обработка** - не держит всё дерево в памяти.
- **Ноль обязательных зависимостей** кроме `pathspec`.
- **Типизирован, покрыт тестами, проверяется в CI.**

## Опции

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `directory` | *(обязательно)* | Корневой каталог для дампа. |
| `-o, --output` | `dump.txt` | Путь к выходному файлу. `-` - вывод в stdout. |
| `-f, --format` | `text` | Формат вывода: `text`, `json`, `markdown`. |
| `--include` | *(нет)* | Glob-шаблон(ы) для включения. Можно повторять. |
| `--exclude` | *(нет)* | Glob-шаблон(ы) для исключения. Можно повторять. |
| `--max-bytes` | `200000` | Обрезать содержимое файла после стольких байт. |
| `--no-gitignore` | выкл | Не учитывать `.gitignore`. |
| `--no-binary-check` | выкл | Считать все файлы текстовыми. |
| `--tokens` | выкл | Вывести оценку количества токенов. |
| `--encoding` | `utf-8` | Кодировка для чтения текстовых файлов. |
| `-q, --quiet` | выкл | Не выводить итоговую сводку в stderr. |

## Пример вывода

```
# Directory dump: /home/you/project

=== FILE: README.md ===
# Мой проект
...

=== FILE: src/main.py ===
def main():
    ...
```
